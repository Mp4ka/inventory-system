# User Stories

## Контекст (ситуация заказчика)

В колледже нет единого реестра компьютерного оборудования: сведения о технике по кабинетам
хранятся в разных местах — бумажные журналы, разрозненные таблицы, память лаборантов.
При инвентаризации, переезде или списании техники информация теряется или дублируется:
невозможно быстро узнать, где находится конкретный системный блок или монитор, в каком он
состоянии и кто за него отвечает.

Заказчик (заведующий компьютерными классами) просит создать консольное приложение, которое
ведёт единый реестр оборудования: просмотр, добавление, изменение, удаление и поиск записей,
а данные хранит в файле, чтобы они не терялись между запусками.

Шаблон: «Как [роль], я хочу [действие], чтобы [польза]».

## US-01. Просмотр оборудования
Как лаборант, я хочу видеть список всего оборудования, чтобы знать, что числится в колледже.

**Критерии приёмки:**
- [x] Выбор пункта «Показать оборудование» выводит все записи.
- [x] Пустой список показывает сообщение «Инвентарь пуст».

## US-02. Добавление записи
Как лаборант, я хочу добавлять новую карточку оборудования, чтобы вести актуальный реестр.

**Критерии приёмки:**
- [x] Корректная запись добавляется в список.
- [x] Две записи с одинаковым инвентарным номером не создаются.
- [x] Пустые обязательные поля (номер, тип, наименование, кабинет, состояние) отклоняются.
- [x] Некорректный ввод не завершает программу аварийно.

## US-03. Поиск по номеру
Как лаборант, я хочу находить оборудование по инвентарному номеру, чтобы быстро узнать, где оно находится.

**Критерии приёмки:**
- [x] Поиск по существующему номеру показывает карточку.
- [x] По неизвестному номеру выводится «Не найдено».
- [x] Пустой номер при поиске не приводит к аварии.

## US-04. Поиск по кабинету
Как зав. кабинетом, я хочу получать список оборудования своего кабинета, чтобы проводить инвентаризацию.

**Критерии приёмки:**
- [x] Поиск по номеру кабинета возвращает все записи этого кабинета.
- [x] Поиск с пустыми полями возвращает весь список.

## US-05. Изменение записи
Как лаборант, я хочу изменять состояние и кабинет оборудования, чтобы реестр отражал реальность.

**Критерии приёмки:**
- [x] Можно изменить состояние и/или кабинет существующей записи.
- [x] Изменение на уже занятый номер отклоняется.
- [x] При изменении несуществующего номера выводится понятное сообщение.

## US-06. Удаление с подтверждением
Как лаборант, я хочу удалять списанное оборудование только после подтверждения, чтобы не потерять данные случайно.

**Критерии приёмки:**
- [x] Удаление выполняется только после ответа «да».
- [x] Ответ «нет» отменяет удаление без изменений.
- [x] Удаление несуществующего номера обрабатывается корректно.

## US-07. Сохранение между запусками
Как пользователь, я хочу, чтобы данные сохранялись в файл и восстанавливались при запуске, чтобы не вводить их заново.

**Критерии приёмки:**
- [x] После выхода и повторного запуска записи сохраняются.
- [x] Отсутствие файла данных не вызывает сбой.
- [x] Повреждённый JSON обрабатывается безопасно без аварийного завершения.
