# Система учёта инвентаря компьютерных классов

Консольное приложение на Python для учёта компьютерного оборудования колледжа:
просмотр, добавление, изменение, удаление и поиск инвентарных записей с хранением
данных в JSON.

## Назначение

Программа помогает лаборанту вести единый реестр оборудования по кабинетам:
кто и когда получил технику, в каком она состоянии и где находится. Все данные
сохраняются в файл `data/inventory.json` и не теряются после перезапуска.

## Хранение данных

- Формат: JSON, файл `data/inventory.json` (список объектов-записей).
- При первом запуске, если файла нет, инвентарь пуст — программа работает без ошибок.
- Если файл повреждён (некорректный JSON) или содержит не список, программа
  безопасно считает инвентарь пустым и не завершается аварийно.
- После каждого добавления, изменения или удаления данные сразу сохраняются в файл.

## Пользовательские сценарии

1. **Первый запуск без файла данных** — показывается пустой инвентарь, можно
   сразу добавлять записи.
2. **Работа с существующим файлом** — записи загружаются автоматически при старте.
3. **Перезапуск** — все изменения, сделанные до выхода, сохранены.
4. **Поиск и изменение** — найти запись по номеру/кабинету, изменить состояние
   или кабинет, удалить с подтверждением.

## Требования

- Python 3.11 или новее
- pytest (для запуска тестов)

## Установка

```bash
# 1. Создать виртуальное окружение
python -m venv .venv

# 2. Активировать его
#    Windows:
.venv\Scripts\activate
#    Linux/macOS:
source .venv/bin/activate

# 3. Установить зависимости
pip install -r requirements.txt
```

## Запуск

```bash
python main.py
```

Запуск тестов:

```bash
python -m pytest
```

## Команды меню

| Пункт | Действие |
|-------|----------|
| 1 | Показать оборудование |
| 2 | Добавить запись |
| 3 | Изменить запись |
| 4 | Удалить запись (с подтверждением) |
| 5 | Поиск (по номеру, кабинету, типу, состоянию) |
| 0 | Сохранить и выйти |

## Структура проекта

```
main.py            — меню и ввод/вывод
inventory.py       — операции с записями (CRUD, поиск, проверка ввода)
storage.py         — чтение/запись JSON
data/inventory.json — данные (12 демонстрационных записей)
tests/test_inventory.py — автоматические тесты
README.md          — этот файл
USER_STORIES.md    — пользовательские истории с критериями приёмки
requirements.txt   — зависимости
Dockerfile         — контейнеризация (дополнительно)
```

## Ограничения

- Один пользователь за раз; нет авторизации и разграничения прав.
- Хранение в одном JSON-файле; не рассчитано на одновременную работу из нескольких процессов.
- Интерфейс текстовый (терминал), графический интерфейс не предусмотрен.
